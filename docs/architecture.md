# Архитектура проекта

## 1. Цель

Проект строится как учебное full-stack веб-приложение для учета чтения, заметок и рекомендаций по книгам с возможностью расширения до VPS-деплоя.

## 2. Технологический стек

- Frontend: React, Vite, React Router, Recharts.
- Backend: Node.js, Express.
- База данных: SQLite.
- Авторизация: JWT + bcrypt.

## 4. Сущности базы данных

### `users`

- регистрационные данные;
- хэш пароля;
- дата создания.

### `books`

- общая карточка книги;
- автор, год, жанры, описание, число страниц;
- демо-книги и пользовательские книги.

### `user_books`

- связь пользователя с книгой;
- статус чтения;
- текущая страница;
- прогресс;
- оценка;
- даты начала и завершения.

### `reading_sessions`

- дата сессии;
- минуты;
- число прочитанных страниц;
- начальная и конечная страницы.

### `notes`

- тип записи: заметка или цитата;
- содержимое;
- номер страницы;
- привязка к книге пользователя.

## 5. Основные API-маршруты

### Аутентификация

- `POST /api/auth/register`
- `POST /api/auth/login`
- `GET /api/auth/me`

### Библиотека

- `GET /api/library/dashboard`
- `POST /api/library/books`
- `PUT /api/library/books/:id`
- `POST /api/library/books/:id/sessions`
- `POST /api/library/books/:id/notes`
- `GET /api/library/books/:id/export`

## 6. Правила логики

- если книга добавлена сразу со статусом `Прочитано`, прогресс автоматически становится `100%`;
- если сессия доводит книгу до конца, статус меняется на `Прочитано`;
- рекомендации считают жанры и авторов из завершенных и высоко оцененных книг;
- демо-аккаунт получает заранее наполненную библиотеку для графиков и тестирования интерфейса.

## 7. Этапы разработки

1. Поднять монорепо-структуру и базовую БД.
2. Реализовать аутентификацию и сидирование.
3. Собрать dashboard с ключевыми формами и графиками.
4. Добавить доработки: цели чтения, экспорт PDF/CSV, деплой.
